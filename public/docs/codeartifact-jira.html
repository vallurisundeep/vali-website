Publish shared library to AWS CodeArtifact

SHARE-100

Publish the existing shared library as a versioned package to a private AWS CodeArtifact npm registry, consumable by downstream projects via pnpm, released through an automated CI/CD pipeline.

Value: governed internal reuse of the already-built library across teams — replacing relative imports and avoiding a public registry.

Definition of Done
  • Package published and installable via pnpm from a clean environment.
  • Releases fully automated — no manual publish.
  • Auth works for both CI (OIDC) and local developers.
  • Consumption and contribution documented.

Provision CodeArtifact domain & npm repository

As a platform engineer I want a CodeArtifact domain and npm-format repository so that we have a private registry to host the shared library.

Acceptance Criteria
  • Domain and repository created via IaC (Terraform / CDK / CloudFormation) — not click-ops.
  • Repository has an upstream to npm-store so transitive deps resolve.
  • public:npmjs external connection associated.
  • Repo endpoint, domain and owner documented; retention policy decided or explicitly deferred.

SHARE-102To Do5 pts

Define IAM roles & authentication strategy

As a DevOps engineer I want scoped IAM policies and a token-auth flow so that CI and developers can read/publish securely.

Acceptance Criteria
  • Separate policies for read (consumers) and read+publish (CI release role).
  • CI role can call GetAuthorizationToken, GetRepositoryEndpoint, sts:GetServiceBearerToken and publish actions.
  • Token retrieval documented via aws codeartifact get-authorization-token.
  • No long-lived credentials committed anywhere; OIDC preferred for CI.

SHARE-103To Do3 pts

Configure the package for publishing (pnpm)

As a library maintainer I want the package configured for the CodeArtifact registry so that pnpm publish targets the right place.

Acceptance Criteria
  • Scoped name, version, publishConfig.registry, files, main/module/types and exports set.
  • .npmrc uses ${CODEARTIFACT_AUTH_TOKEN} from env — token never hard-coded.
  • Published tarball verified via pnpm pack --dry-run to include build output + types.
  • If monorepo: single-package vs pnpm -r publish behavior confirmed.
⚑ Note: aws codeartifact login --tool npm writes npm config that pnpm may not read — use the ${...} token in .npmrc. Most common 401 cause.

SHARE-104To Do5 pts

Build a new CI/CD release pipeline

As a maintainer I want an automated pipeline so that merges/tags publish the library without manual steps.

Acceptance Criteria
  • New pipeline runs install → lint → test → build → publish.
  • Authenticates to CodeArtifact via the CI IAM role (OIDC preferred).
  • Publish runs on the release trigger (tag or main merge).
  • Duplicate-version publish (409) fails gracefully without red-failing the run.

Automated versioning & release strategy

As a maintainer I want a defined versioning flow so that versions are consistent and traceable.

Acceptance Criteria
  • SemVer strategy chosen (Changesets recommended for pnpm; or semantic-release).
  • Version bump + changelog generation automated.
  • Git tag created per release and linked to the published version.
  • Pre-release / next channel decision documented or deferred.
