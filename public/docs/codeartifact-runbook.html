Publishing the Shared Library to AWS CodeArtifact

End-to-end procedure for packaging an already-built pnpm library, provisioning a private CodeArtifact registry, and shipping releases through an automated pipeline.

01

Prerequisites

Confirm the following before touching AWS. Every command below assumes these are in place.

AWS CLI v2
Authenticated profile with rights to CodeArtifact + IAM (aws sts get-caller-identity succeeds).
pnpm ≥ 8
The library builds cleanly with pnpm build and produces a dist/ output.
Node ≥ 18
Matches the version your CI runner and consumers use.
Package scope
An org scope decided, e.g. @yourorg. Placeholders below use @yourorg/shared-lib.

Set these shell variables once — the rest of the runbook reuses them.

env.sh
export AWS_DOMAIN=yourorg
export AWS_ACCOUNT=111122223333
export AWS_REGION=us-east-1
export CA_REPO=shared-libs
export CA_HOST=${AWS_DOMAIN}-${AWS_ACCOUNT}.d.codeartifact.${AWS_REGION}.amazonaws.com
02

Provision the registry

Create the domain and an npm-format repository. Attach the public npm-store upstream so transitive dependencies still resolve.

provision.sh
# 1 · domain (namespace for repos + shared storage)
aws codeartifact create-domain --domain $AWS_DOMAIN

# 2 · public npm proxy (so npmjs deps resolve through us)
aws codeartifact create-repository --domain $AWS_DOMAIN \
  --repository npm-store

# 3 · our private repo, with the proxy as upstream
aws codeartifact create-repository --domain $AWS_DOMAIN \
  --repository $CA_REPO --upstreams repositoryName=npm-store

# 4 · associate the external npmjs connection
aws codeartifact associate-external-connection --domain $AWS_DOMAIN \
  --repository npm-store --external-connection "public:npmjs"
i

Do this in IaC, not the console. The commands above document intent; the source of truth should be Terraform / CDK / CloudFormation so the registry is reproducible and reviewable.

03

IAM & authentication

Split access into two policies: read for consumers, read + publish for the release role. Auth is always a short-lived bearer token — never long-lived credentials in a repo.

Minimum publish permissions

publish-policy.json
{
  "Effect": "Allow",
  "Action": [
    "codeartifact:GetAuthorizationToken",
    "codeartifact:GetRepositoryEndpoint",
    "codeartifact:ReadFromRepository",
    "codeartifact:PublishPackageVersion",
    "codeartifact:PutPackageMetadata",
    "sts:GetServiceBearerToken"
  ],
  "Resource": "*"
}

Fetch a token

auth.sh
export CODEARTIFACT_AUTH_TOKEN=$(aws codeartifact get-authorization-token \
  --domain $AWS_DOMAIN --domain-owner $AWS_ACCOUNT \
  --query authorizationToken --output text)
i

Prefer OIDC in CI. Give the pipeline an IAM role assumed via OIDC rather than static access keys — no secrets to rotate, and the token above is minted per run.

04

Configure the package

Point pnpm at the CodeArtifact registry and make sure the published tarball contains exactly what consumers need.

package.json

package.json
{
  "name": "@yourorg/shared-lib",
  "version": "1.0.0",
  "main": "dist/index.js",
  "module": "dist/index.mjs",
  "types": "dist/index.d.ts",
  "exports": { ".": { "types": "./dist/index.d.ts",
                "import": "./dist/index.mjs",
                "require": "./dist/index.js" } },
  "files": ["dist"],
  "publishConfig": { "registry": "https://${CA_HOST}/npm/${CA_REPO}/" }
}

.npmrc

.npmrc
# scope → registry mapping
@yourorg:registry=https://${CA_HOST}/npm/${CA_REPO}/
# auth token pulled from the environment — never hard-coded
//${CA_HOST}/npm/${CA_REPO}/:_authToken=${CODEARTIFACT_AUTH_TOKEN}
//${CA_HOST}/npm/${CA_REPO}/:always-auth=true
!

The pnpm token gotcha. aws codeartifact login --tool npm writes to npm's config, which pnpm does not always read. The reliable path is to export CODEARTIFACT_AUTH_TOKEN and reference it via ${...} in .npmrc, as above. This is the single most common cause of 401s.

05

Local publish (dry run first)

Validate the tarball contents before the pipeline exists. Inspect, then publish.

release-local.sh
source env.sh && source auth.sh   # set vars + token
pnpm install && pnpm build

# inspect exactly what will ship — no dist/ = misconfigured "files"
pnpm pack --dry-run

# publish (restricted access for a private scope)
pnpm publish --access restricted --no-git-checks
i

Verify in AWS. Run aws codeartifact list-package-versions --domain $AWS_DOMAIN --repository $CA_REPO --format npm --namespace yourorg --package shared-lib and confirm your version is listed.

06

Automated CI/CD pipeline

The new pipeline runs install → lint → test → build → publish. The example uses GitHub Actions with OIDC; the shape is the same on GitLab / Jenkins / CodePipeline.

.github/workflows/release.yml
on:
  push:
    tags: ["v*"]
permissions: { id-token: write, contents: read }
jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::111122223333:role/ca-publisher
          aws-region: us-east-1
      - uses: pnpm/action-setup@v4
      - run: |
          export CODEARTIFACT_AUTH_TOKEN=$(aws codeartifact \
            get-authorization-token --domain yourorg \
            --query authorizationToken --output text)
          pnpm install --frozen-lockfile
          pnpm lint && pnpm test && pnpm build
          pnpm publish --access restricted --no-git-checks
!

Idempotent re-runs. Republishing an existing version fails with 409. Gate publish on a version bump (Changesets) so a re-run of the same tag doesn't red-fail the pipeline.

07

Consume from a downstream project

Prove the loop end-to-end from a clean checkout.

consumer.sh
# same scope→registry line + token in the consumer's .npmrc
export CODEARTIFACT_AUTH_TOKEN=$(aws codeartifact get-authorization-token \
  --domain $AWS_DOMAIN --query authorizationToken --output text)

pnpm add @yourorg/shared-lib
pnpm build   # types resolve, transitive deps pull via npm-store
08

Troubleshooting

401 Unauthorized
Token expired (12h max) or ${CODEARTIFACT_AUTH_TOKEN} not exported in the shell running pnpm. Re-run the auth step.
403 Forbidden
IAM role missing PublishPackageVersion / PutPackageMetadata, or wrong --domain-owner.
409 Conflict
That exact version already exists — bump the version; CodeArtifact versions are immutable.
404 on a dep
Transitive package not fetched yet — confirm the public:npmjs external connection on npm-store.
pnpm ignores login
Use the ${...} token in .npmrc rather than codeartifact login. See Phase 04.
